# Hooky — Bug Fixes (31 Aug 2026)

Fixes made during closed testing, ahead of resubmitting for Production access.
Useful as evidence of active testing/response when Google asks about testing methodology.

All three issues below were found through hands-on use of the app for actual
crochet projects — not automated testing — which is exactly the kind of
real-world tester engagement Google's production access review looks for.

## 1. Needle/hook size scanner misread decimal points

**Issue:** Scanning a crochet hook engraved "5.5mm" sometimes proposed "55mm" — a
size that doesn't exist. Root cause: ML Kit's on-device OCR occasionally drops
the decimal point on shallow embossed markings (either collapsing it to a
stray space, or dropping it entirely).

**Fix:**
- A space between two digits is now treated as a missing decimal point
  (`"5 5mm"` → `5.5mm`).
- A bare 2-digit reading with no separator that isn't a real whole-mm hook
  size (only 4, 5, 6, 8, 9, 10, 12, 15, 16, 19, 20, 25mm exist) has the decimal
  point reinserted (`"55mm"` → `5.5mm`).
- Crochet hook readings above 35mm are now rejected outright rather than
  proposed, since no real hook is that large. This cap only applies to
  crochet hooks — knitting needle scans are unaffected (fixed a related bug
  where the Needle form always scanned in "hook" mode regardless of the
  instrument type actually selected).

**Files:** `data/scanner/NeedleParser.kt`, `data/scanner/YarnLabelScannerService.kt`,
`ui/yarns/form/YarnFormViewModel.kt`, `ui/pieces/form/PieceFormViewModel.kt`,
`ui/needles/form/NeedleFormViewModel.kt`

## 2. Dates displayed in raw ISO format instead of a readable one

**Issue:** After picking a date, fields showed `2026-07-16` instead of a
human-readable format — confusing for end users.

**Fix:** All user-facing dates now display as `dd/MM/yyyy` (e.g. `16/07/2026`).
Storage is unchanged (still ISO-8601 internally). Since this is a numeric
format with no translated words, it's consistent across all three app
languages (EN/ES/PT-BR) automatically.

**Where fixed:** Piece edit form (date picker fields), Piece detail screen,
Dashboard "Finished" label, Yarn detail screen (was previously showing the
raw ISO string with no formatting at all).

**Files:** new `util/DateFormatUtil.kt`, `ui/pieces/form/PieceFormScreen.kt`,
`ui/pieces/detail/PieceDetailScreen.kt`, `ui/dashboard/DashboardScreen.kt`,
`ui/yarns/detail/YarnDetailScreen.kt`

## 3. "Sold Date" and "Sold Price" shown before a piece was actually sold

## 15. Piece detail showed no yarns once ball counts were set
**Found:** 2026-11-02, while planning part-ball yarn amounts.

**Problem:** Since balls-per-yarn was added, pieces save their yarns as
`[{"yarnId":…,"balls":…}]`, but the piece detail screen still read the old
list of IDs. Reading failed silently, so "Yarns used" disappeared for every
piece saved after that change.

**Fix:** One shared reader (`parseYarnUsages`) for both formats, used by the
form, the piece detail and the yarn detail. The detail now shows the amount
("Bloom · 2½ balls"). In the same change: part balls (2⅓, 2.5) can be typed or
picked, and the yarn detail shows "Used in pieces" and "Left".

**Files:** `domain/model/YarnUsage.kt`, `util/YarnAmountFormat.kt`,
`ui/pieces/detail/PieceDetailScreen.kt`, `ui/pieces/form/PieceForm*.kt`,
`ui/yarns/detail/YarnDetail*.kt`; test `test/.../util/YarnAmountFormatTest.kt`

**Verified:** unit tests pass; checked on the Pixel_6 emulator in PT-BR at
360dp: 2½ saved, shown on the piece detail, reloaded in the form; yarn with
5 owned shows used 2½ / left 2½.

## 16. "Pick the colour from a photo": buttons hidden behind the navigation bar
**Found:** 2026-11-03 on the owner's phone after 1.10.0 went live (three-button navigation).

**Problem:** The full-screen colour picker's Cancel / Confirm row was drawn behind
Android's three-button navigation bar, so the colour could not be confirmed. Full-screen
Compose dialogs don't receive the system bar sizes by default, so the padding meant to
keep the row clear did nothing. The emulator used gesture navigation and hid the problem.

**Fix:** `decorFitsSystemWindows = false` on the colour picker and the full-screen photo
viewer, so their padding knows the bar sizes.

**Files:** `ui/yarns/form/ColorFromPhotoDialog.kt`, `ui/components/FullScreenPhotoViewer.kt`

**Verified:** Pixel_6 emulator switched to three-button navigation: Cancel / Confirm sit
above the bar and work. Released as 1.10.1 (build 29).

## 15. Colour picker buttons still hidden on Samsung (Android 16)
**Found:** 2026-11-03, on a real Samsung Galaxy S22 (Android 16, three-button navigation) with
1.10.1 from Google Play, while recording a promo video. In "Pegar a cor da foto", Cancelar and
Confirmar were at y 2295–2340 of a 2340px screen, under the navigation bar; Back was the only
way out, so the colour could not be confirmed.

**Cause:** the 1.10.1 fix padded the dialog by the navigation bar inset, but on this device the
dialog window receives a zero navigation bar inset (the status bar inset arrives correctly).

**Fix (1.10.2):** the action row moved to the top of the picker under the hint text, and the
bottom keeps `max(navigation inset, 56dp)`. Button labels use `WordSafeText` so they shrink
instead of breaking mid-word on narrow screens / large fonts. Verified on the emulator with
three-button navigation at 360dp and 308dp widths.

# Fixes from closed-testing tester feedback (8 Sept 2026)

Unlike the fixes above (found through the developer's own hands-on use), these
three were reported directly by a closed-testing tester using the app on their
own phone — exactly the kind of independent tester engagement and iteration
Google's production-access review is looking for.

## 4. Dialog buttons nearly invisible in dark mode

**Tester report:** "The button Keep Editing is almost invisible on my phone.
Perhaps it's a night theme issue? Similar the Confirm button when selecting a
yarn in the project."

**Root cause:** Several dialog buttons set a custom `containerColor` (Slate or
BrandPurple) without an explicit `contentColor`. Since these are custom colors
rather than registered Material theme roles, Compose couldn't auto-compute a
readable text color and fell back to a low-contrast default — dark text on a
dark button, on a dark dialog, in dark mode.

**Fix:** Added explicit `contentColor = White` to every affected button (7
locations): the "Keep editing" unsaved-changes dialog (Piece, Yarn, and Stitch
forms), the "Confirm" button in the Piece form's yarn/needle/stitch picker
dialog, the row-counter "Save" dialog on the Piece detail screen, and the
"Save" button in the Stitches "Ideas" dialog.

**Files:** `ui/pieces/form/PieceFormScreen.kt`, `ui/yarns/form/YarnFormScreen.kt`,
`ui/stitches/form/StitchFormScreen.kt`, `ui/pieces/detail/PieceDetailScreen.kt`,
`ui/stitches/list/StitchListScreen.kt`

## 5. Inconsistent Create/Save button styling

**Tester report:** "The Create Piece button and other 'save' buttons are not
the same style as the Save Changes button when editing. Consistent styling
would be nice here I think."

**Root cause:** In the Piece, Yarn, and Stitch forms, the same primary submit
button switched color depending on mode — Slate (dark navy) when creating,
BrandPurple when editing — so "Create Piece" and "Save Changes" looked like
two different buttons despite being the identical action. The Needle form
already handled this correctly (always Slate), which also matches the app's
own documented design system (Slate for primary actions; purple reserved for
brand/accent elements, not general buttons).

**Fix:** Made the Piece, Yarn, and Stitch forms' save button always use Slate,
regardless of create/edit mode — matching the Needle form's existing correct
behavior and the app's documented B&W-minimalist design guidelines.

**Files:** `ui/pieces/form/PieceFormScreen.kt`, `ui/yarns/form/YarnFormScreen.kt`,
`ui/stitches/form/StitchFormScreen.kt`

## Verification
All changes compiled cleanly (`./gradlew :app:compileDebugKotlin`). Not yet
built into a release — pending before the next closed-testing upload.

# Fixes from real-user screen grabs, ES/PT open-testing release (16 Sept 2026)

Found from actual screen recordings of the app running in Spanish and
Portuguese — not synthetic testing — after Google approved production
access. Shipped as a scoped open-testing release (versionCode 14 /
versionName 1.4.7) kept deliberately separate from unrelated in-progress
feature work, so this round stays pure quality/bug fixes.

## 6. Destination badge hyphenating mid-word on the Dashboard

**Report (screen grab):** On the in-progress card carousel, the destination
badge ("Para regalo" in ES, "Para Presente" in PT) wrapped letter-by-letter
across up to 6 lines — e.g. "regalo" broke into "regal" / "o", and "Presente"
into "Pa"/"ra"/"Pr"/"es"/"en"/"te".

**Root cause:** The in-progress card is a fixed 160dp box holding two badges
side by side in a plain `Row`. With no `weight()` modifiers, the second
(destination) badge only gets whatever width is left over after the first
(status) badge claims its own — often just a few dp. Compose's `Text` only
breaks within a word when even the narrowest single-word line can't fit that
constraint, which is what was happening here.

**Fix:** Replaced the `Row` with a `FlowRow` for this badge pair, so when the
destination badge doesn't fit next to the status badge, it now wraps onto its
own line as a whole chip instead of hyphenating internally. Also shortened
the ES and PT destination labels to fit more comfortably: ES "Para regalo" →
"Regalo", "A la venta" → "Venta"; PT "Para Presente" → "Presente", "Para
Venda" → "Venda".

**Files:** `ui/dashboard/DashboardScreen.kt`, `res/values-es/strings.xml`,
`res/values-pt-rBR/strings.xml`

## 7. Broken tutorial link in the Spanish Stitches → Ideas tab

**Issue:** The "Crochet y Dos Agujas de Pat" YouTube channel link (used by 4
Spanish stitch tutorial entries) 404'd — the URL had an erroneous `MV` suffix
(`@CrochetydosagujasdePatMV`) that was never a valid channel handle.

**Fix:** Verified every EN/ES/PT Ideas-tab link by fetching it directly;

**Files:** `data/suggestions/StitchSuggestionsData.kt`

## 8. Settings screen entirely unlocalized for ES/PT

**Issue:** The Settings screen was 100% hardcoded in English regardless of
the app's selected language — section headers (Appearance/Language/
Currency/Backup/Help/Beta/Debug), theme and language picker options,
currency names, backup export/import text, and the tester/beta section all
showed English text to Spanish and Portuguese users.

**Fix:** Fully localized to ES/PT. Language picker labels now show in the
app's own language (e.g. "Inglés"/"Espanhol") while each language's own
endonym sublabel ("English", "Español") stays untranslated by design.
Currency names are now translated separately from the currency code/symbol,
which remain universal.

**Files:** `ui/settings/SettingsScreen.kt`, `ui/settings/CurrencyPrefs.kt`,
`res/values/strings.xml`, `res/values-es/strings.xml`,
`res/values-pt-rBR/strings.xml`

## 9. Doubled "h" in the Price Calculator labor breakdown (EN/ES/PT)

**Fix:** Removed the extra " h" from `calculator_breakdown_labor`, so the

**Files:** `res/values/strings.xml`, `res/values-es/strings.xml`,
`res/values-pt-rBR/strings.xml`

## 10. ES/PT labels breaking mid-word again after release 21

**Issue:** Reported from a tester's phone on 2026-10-06: on the Piece detail
screen the Edit / Clone / Archive buttons showed "Edit-ar", "Clon-ar",

**Fix:** Piece detail action row now uses the same tight padding +

**Files:** `ui/components/WordSafeText.kt` (new),

## 14. Photo editor: first rotate-and-save came out wrong

**Found:** 2026-10-25 by the developer while recording a tutorial on a Samsung
Galaxy S22 (Android 16), visible in the screen recording. Rotating a photo and
saving did not give the result shown in the editor; opening the editor again
showed the photo turned differently, and only a second rotate-and-save worked.
Happened every time with photos from the app camera and the phone gallery.

**Cause:** phone cameras save photos sideways with an EXIF orientation tag.
The editor preview (Coil) honours the tag, but the save decoded the file with
`BitmapFactory`, which ignores it, so the rotation was applied to the raw
sideways picture. The saved file has no tag, which is why the second edit
worked. The same decoder feeds the piece share card and the yarn label /
needle size scanners, so those could also get sideways photos.

**Fix:** `decodeSampledBitmapFromFile` now applies the EXIF orientation after
decoding (all eight orientations), so every caller gets the photo upright.

**Files:** `util/BitmapUtils.kt`; test `androidTest/.../util/BitmapUtilsTest.kt`

**Verified:** `BitmapUtilsTest` (rotate 90, rotate 270, normal) passes on the
Pixel_6 emulator. Not yet checked in the app on the phone.

# 1.10.3 / build 31 — fixes found using the app for real (7 Nov 2026)

All found by the developer using Hooky for her own pieces and stash, or while recording the
1.10 social videos on a Samsung S22, then checked on the emulator in PT-BR and ES.

1. **Prices and costs typed with a comma were lost** (PT/ES). Number fields only understood
   "12.50", so "12,50" was saved as empty, silently. New shared parser accepts both
   (`util/DecimalInput.kt`, unit-tested), used by every decimal field (pieces, yarns, needles,
   price calculator). Verified: "3,40" / "12,50" saved and shown as €3,40 / €12,50.
2. **Skip on the welcome screens didn't work.** The swipeable pages were drawn on top of the
   "Skip" button, so taps never reached it. Moved it on top; verified it opens the dashboard.
3. **Importing a backup replaced everything with no warning.** Now shows what the file
   contains (pieces, yarns, stitches, needles, date) and asks first; keeps a copy of the current
   data and offers "Undo last import" in Settings. Verified import, undo and re-import.
4. **Backup export couldn't be saved on the phone** (share menu only, and "Files by Google ·
   Download" silently failed). New "Save to phone" uses the system file picker. Verified a file
   saved to Downloads with the real data.
5. **Report totals didn't match the rows** (total profit counted the full price of pieces with
   no cost). Total and "by customer" now use the same rule as each row. Gifts and own pieces no
   longer count as revenue; a sold price only counts once the piece is Sold. Verified: rows and
   customer rows add up to the total.
6. **Gift recipient showed on pieces for sale** after the destination changed. Shown only for
   gift destinations now (the name is kept, so switching back restores it).
7. **Scanned yarn material stuck on hidden lines** in a one-line field. Scanned text is joined
   into one line; the composition field shows up to 3 lines.
8. **Dashboard content scrolled under the clock** with nothing behind it. A purple strip now
   stays behind the status bar.
9. **Stash total showed "13,17 novelos".** Totals now round to a crafter fraction: "≈ 13¼".
10. **Excel export**: count totals showed "14.00" (now "14"); dates saved as dd/MM/yyyy are now
    real date cells (US-English Sheets read them as MM/dd).
11. **Yarns "Por cor" kept the old first yarn in view** after sorting; now goes to the top.
12. **Long piece/stitch names were cut with no "…"**; now 2 lines with an ellipsis.
13. **Cloning a yarn kept its colour code** (e.g. "D-17"); the copy now starts without one.
